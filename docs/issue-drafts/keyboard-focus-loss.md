状態：[Issue #10として起票済み](https://github.com/rattokun-1/dashcloudly-learning-web/issues/10)。関連：#4。1つの画面遷移時のフォーカス管理の問題の確認記録です。

- 確認コードのコミット：`13d0a21c8975161bf9b83138c1b7a7a55e6aaa7d`（アプリコードの変更なし）
- 共通公開用リポジトリの生成デモ、未ログイン、Local／Connectedの設定なし
- Windows build 10.0.26300.0、Chrome 155.0.8059.85（ヘッドレス）
- ビューポート：1440×900、390×844 CSS px、ズーム100%
- 入力：ブラウザーのキーボードAPIでTab・Enter。外部リクエストを遮断し、localhostだけ許可
- 実教材・利用者情報・画面添付なし。英語版／古文版の本番は未検証

## 再現手順

1. [ガイドの準備](../KEYBOARD-CHECK.md#1-準備)に従い、新規プロファイルで生成デモを開く。
2. 初回案内をTab・Enterで終了し、初期の6択形式を使う。
3. Tabで`#btn-start-quiz`へ移動し、Enterを1回押す。
4. 第1問が表示された直後のフォーカス枠を確認する。
5. Tabで任意の選択肢へ移動しEnter。解答表示後のフォーカスを確認する。
6. Tabで`#next-btn`へ移動してEnter。第2問表示後のフォーカスを確認する。

Tabの回数やランダムな出題内容は固定しません。選ぶ答えが正解かどうかも前提にしません。

## 期待する動作

開始後・次問表示後は表示中の第1選択肢、解答表示後は「次の問題へ」にフォーカスが移り、枠が見えます。BODY、非表示ボタン、非表示画面に残りません。

## 実際の動作

| 遷移 | 1440×900 | 390×844 |
| --- | --- | --- |
| 開始直後 | `document.activeElement`がBODY | BODY |
| 回答直後 | BODY | BODY |
| 次問表示直後 | 非表示になった`#next-btn`に残る | BODY |

生成項目の第1問→第2問で再現しました。フォーカスを目で追えず、次の操作対象をTabで探し直す必要があります。DevToolsのConsoleからフォーカスを直さずに再現できます。

## 切り分けと確認範囲

`startNormalQuiz()`、`renderQuestion()`、`nextQuestion()`の画面更新時のフォーカス管理を調査対象にできます。これは調査候補であり、原因の断定ではありません。今回コードは変更していません。Edge・Firefox・Safariと実機は未確認です。

再確認時は`git rev-parse HEAD`と[ガイドの記録欄](../KEYBOARD-CHECK.md#4-結果を記録する)を追記してください。個人情報・実教材・保存データを添付しないでください。

PR #9マージ後の`5b49303`、Chrome 155.0.8059.85、1440×900・390×900で再確認。Tab・Enterで操作し、各画面更新から2フレーム待って観測すると、K2〜K4はいずれもBODYにフォーカスが移りました。初回案内完了だけを端末内のテスト設定で準備しています。フォーカスや学習関数は直接実行していません。
